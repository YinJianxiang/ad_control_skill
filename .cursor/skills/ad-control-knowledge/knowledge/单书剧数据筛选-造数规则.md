# 单书/剧数据筛选：通用造数规则

当规则把「单书/剧数据筛选」设为**开启**时使用。  
本知识是**跨业务线、跨用例**的通用造数约定，不绑定某一条规则或某一个 case。

## 一句话

管控条件命中只说明「这条广告/项目/渠道」过了阈值；  
单书/剧筛选还要求：**同一本书/剧在本业务线大盘上**也过筛选。  
两边都过，才会真正落管控结果。只造广告侧、不造书剧大盘，等于筛选未通过。

## 何时启用本造数

规则上同时满足：

1. 「单书/剧数据筛选」= 开启  
2. 填了消耗阈值、当日 ROI 阈值；部分业务线还会填「连续 3 天分日 ROI」阈值  

关闭该筛选时，不必造本节的大盘数据。

## 造数分两层（必须同一 book_id）

### A. 管控条件层（原有造数）

按规则的业务线、维度、时间、聚合、指标，造**维度主表**数据，使条件 HIT 或 MISS。  
这一层与筛选无关，规则怎么配就怎么造。

### B. 书剧大盘层（筛选开启后必补）

再按 **book_id** 造「业务线 × 书/剧 × 分日」大盘，使筛选判定为通过（或故意不通过）。

硬约束：

- 主表行上的 `book_id` 与大盘行上的 `book_id` **必须相同**  
- 大盘看的是**该书在该业务线下的汇总**，不是单条广告日表凑数  
- 大盘一律走**渠道日表**（按书聚合）；不要误造到广告日表/项目日表代替  

## 筛选「通过」时大盘要长什么样

页面上的三项，对应造数口径如下（比较符与页面一致：消耗用「大于」，ROI 用「小于」）。

| 页面条件 | 造数要求 |
|---|---|
| 连续 3 天分日消耗 > 阈值 | 见下方「日期窗口」：窗口内**每一天**的书剧汇总消耗都 **> 消耗阈值** |
| 当日广告变现/对应 ROI < 阈值 | **当天**该书剧汇总 ROI **< 当日 ROI 阈值** |
| 连续 3 天分日 ROI < 阈值（有填才造） | 窗口内**每一天**的书剧汇总 ROI 都 **< 该阈值** |

推荐造「稳稳通过」的安全余量（阈值以规则为准，下表为倍数建议）：

- 每天消耗：`阈值 + 余量`（例如阈值 100 → 造 150）  
- 每天 ROI：明显小于阈值（例如阈值 1.0 → 造 0.6：分子/消耗 = 0.6）  

比率类指标：先分别汇总分子、分母，再相除；不要只改一个「ROI 列」却与分子分母不一致。

## 日期窗口（按业务线）

| 业务线类型 | 消耗要覆盖的日期 | 分日 ROI 要覆盖的日期 |
|---|---|---|
| 端原生免费 / 端原生付费 / 新媒体短剧 / 新媒体免费短剧 | 今天、昨天、前天（连续 3 天） | 若填了「连续 3 天分日 ROI」：同样三天 |
| 新媒体短篇 / 新媒体免费小说 / 客户端付费小说 / 客户端付费短剧 | **只要当天** | 以规则是否配置「连续 3 天分日 ROI」为准；短篇等若配置了，按三天造 |

缺一天、某一天消耗未过线、或某一天 ROI 未过线 → 筛选不通过。

## 各业务线：大盘表与 ROI 分子字段

大盘一律：**渠道日表 + 按 book_id 汇总**。  
ROI = 当日分子汇总 ÷ 当日消耗汇总。

| 业务线 | 编码 | 大盘表 | ROI 分子字段（写入列） | 备注 |
|---|---|---|---|---|
| 头条端原生-免费 | cpsdyfree | `ad_advertiser_online_free_channel_day` | `micro_game_0d_ltv` | 广告变现 ROI |
| 新媒体-免费短剧 | cpsvideomf | `ad_advertiser_online_free_channel_day` | `n_predict_cpm` | 预估类 ROI |
| 头条端原生-付费 | cpsdy | `ad_advertiser_online_pay_channel_day` | `active_pay_intra_one_day_amount` | 激活后 24h 付费金额 |
| 新媒体-短剧 | xmtplay | `ad_advertiser_online_pay_channel_day` | `cz_h12` | ROI_H12 分子 |
| 新媒体-短篇 | cpsshort | `ad_advertiser_online_pay_book_channel_day` | `cz_h12` | 默认看当天消耗+ROI |
| 新媒体-免费小说 | cpsfree | `ad_advertiser_online_pay_book_channel_day` | `n_predict_cpm`、`n_recharge_discount` 等补贴口径相关列 | 默认看当天；分子按该线补贴 ROI 口径凑 |
| 客户端-付费小说 / 付费短剧 | cltmain / cltplay | `ad_advertiser_client_pay_channel_day` | 以该线书剧 ROI 口径为准 | 默认看当天消耗 |

骨架字段建议与主表一致：`pline_form`、`book_id`、`channel_code`（可用同一测试渠道）、`cdate`、以及状态类字段按该表惯例填齐。

## 故意让筛选不通过（负向）

任选其一即可（仍保持管控条件层可命中，便于区分「条件命中但筛选拦住」）：

- 不造大盘，或 book_id 对不上  
- 三天窗口缺一天  
- 某一天汇总消耗 ≤ 消耗阈值  
- 某一天汇总 ROI ≥ 对应 ROI 阈值  

## 清理

- 主表：按测试 `channel_code`（及既有清理列）删  
- 大盘渠道日表：按同一测试 `channel_code` + `book_id` + 造数覆盖的 `cdate` 删  
- 两层都要进清理清单，禁止只清主表留大盘脏数据  

## 常见错误（禁止）

1. 只造广告/项目日表，以为能代替书剧大盘  
2. 主表与大盘 `book_id` 不一致  
3. 造了「当天」却漏了「昨天/前天」（需要三天的业务线）  
4. 消耗用 `>=` 阈值造数——页面是 **>**，造成等于阈值会不过  
5. ROI 用 `<=` 阈值——页面是 **<**，造成等于阈值会不过  
6. 把本知识写成某个 case 的特例，而不是按规则字段通用推导  

## 与用例的关系

用例只需声明：筛选是否开启、三个阈值、业务线与维度。  
造数引擎/人工造数按本知识推导大盘表、日期窗口、分子字段和通过/不通过数值；**不要**为单个 case 再写一套互斥口径。
